# 機能一覧定義書 (Feature List)

## 1. フロントエンド機能 (Nuxt.js / Client Side)
主にユーザーインターフェースと、ローカルでの一時的な状態管理を担当する。

### 1.1 ゲームエンジン・UI
* **盤面レンダリング**: 16x16のグリッド描画、開封・未開封・爆弾・数字の表示。
* **インタラクション**: 左クリック（開封/コミットキュー）、右クリック（フラッグ配置）。
* **楽観的更新**: 通信ラグを感じさせないよう、クリックした瞬間にローカルで仮の開封表示を行う。
* **演出システム**: ライフ減少時のシェイク、残り3秒のタイマー警告音・赤点滅、爆発エフェクト。

### 1.2 状態同期・通信
* **WebSocketクライアント**: DOからの最新状態（GameState）の受信と、ローカル状態の同期。
* **コミットバッファ**: 10秒間の操作ログ（ActionLog）を一時保存し、一括送信する。

### 1.3 ユーザー体験 (UX)
* **認証UI**: ゲストログイン、またはアカウント登録。
* **戦績表示**: D1から取得したレート推移や勝敗データのグラフ表示。

## 2. バックエンド機能 (Cloudflare Workers / DO / D1)
判定の正当性、データの永続化、リアルタイムの同期を担当する。

### 2.1 ゲームサーバー (Durable Objects)
* **ルーム管理**: 2人のプレイヤーを1つのDOインスタンスに紐付け。
* **盤面生成**: 爆弾位置のランダム決定と周囲の数計算（クライアントには隠蔽）。
* **コミット検証 (判定コア)**:
    * 受信したActionLogの整合性チェック。
    * 爆弾ヒット時のライフ計算、安全マスのスコア加算。
    * 0マス時のオートオープン再帰処理。「現在の盤面状態 + ユーザーのクリック位置」を引数に取り、「新たに開示されるべき座標リスト」を返す純粋関数とする。
* **権威タイマー**: 厳密な10秒計測。タイムアップ時に強制的にターンを終了させ、ペナルティを課す。
* **状態配信**: 判定結果を全プレイヤーへWebSocketでブロードキャスト。

### 2.2 マッチング・システム (Workers)
* **待機列管理**: レートの近いプレイヤー同士、または同じ合言葉を持つプレイヤー同士をマッチング。
* **DOインスタンス割り当て**: マッチング成立時に新しいゲームセッション（DO）を開始。

### 2.3 データ永続化 (D1 / SQL)
* **試合ログ保存**: 決着時、スコア・勝敗・レート変動を保存。
* **ランキング計算**: 全ユーザーのレートに基づくリーダーボードの集計。

## 3. 機能・責務の分担表

| 機能 | フロントエンド | バックエンド | 備考 |
| :--- | :---: | :---: | :--- |
| 爆弾の配置決定 | - | ○ | 不正防止のためサーバーのみ |
| 0マスの連鎖開封 | ○ (表示のみ) | ○ (論理計算) | サーバーの結果が優先される |
| フラッグ(旗)の管理 | ○ | - | 相手に非表示のためローカルのみ |
| 10秒タイマー | ○ (表示用) | ○ (判定用) | サーバータイマーが絶対 |
| レート計算(ELO) | - | ○ | 決着時にD1更新と共に実行 |
